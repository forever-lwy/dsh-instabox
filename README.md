# DSH Instabox

适用于 **DeepSeek Harness**（当前在 `0.2.2-rc.3` 上构建测试，不按 dsh 版本拦截加载） 的 Instabox 云电脑插件。独立的 Host 插件、浏览器面板及模型工具，使用官方 API 和固定版本 `@insforge/instabox-sdk@0.6.0`。

## 安装

在 DSH「插件 → 添加插件」输入下面的来源，确认安装并启用：

```text
github:forever-lwy/dsh-instabox
```

仓库默认分支是 `release`，其中每个提交都是某次发版的源码加上构建好的 `lib/`，并去掉了 `prepare`，所以安装时不装 devDependencies、不构建。dshmarket 按默认分支上 `package.json` 的版本号判断是否有更新，点击更新时安装 `release` 的最新提交。不要安装 `master`：它只有源码，安装时会靠 `prepare` 拉全部 devDependencies 现场构建。

包名自 0.1.4 起为 `@forever-lwy/dsh-instabox`，以免与 npm 和插件市场目录里的同名插件混淆。从旧的 `dsh-instabox` 版本包迁移时，先卸载旧的 `dsh-instabox`，再安装上面的来源；两者注册同一宿主行，不能同时安装。宿主行 id 和设置命名空间不变。

插件提供「Instabox」主导航入口和设置页面。首次打开设置，填入 Instabox API Key 并保存；界面仅显示是否配置，不会读回密钥。普通设置存入 DSH_HOME 下的插件独立文件，密钥交给 DSH credentials 服务保存。

推荐使用**创建机器的本人账号的个人 API Key**：机器执行需要 `machines:read` 和 `machines:write`，删除机器需要 `machines:delete`，快照管理需要对应的 `images:*` 权限。只读 Key 无法启动桌面。

官方桌面分享接口不接受 workspace API Key；该 Key 可执行其他有权限的操作，但生成桌面 viewer 会得到 403。当前版本以个人 Key 的官方 viewer 为桌面接入方式，不提供 workspace Key 的自建 VNC WebSocket 中继。

是否需要重启以安装界面提示为准。不要用 `link:`、目录依赖或模块路径把源码目录接入常用 profile。

## 桌面与人工接管

### 在对话中使用

`0.1.2` 增加对话内桌面。进入「Instabox 设置 → 对话中的桌面位置」，选择：

- **最新消息下方**：当前对话使用云机时，消息末尾自动显示桌面卡片；新消息到来后，卡片仍在最后。可观看、放大、人工接管，或收起为一个入口按钮。
- **右侧栏预览**：在原生右侧栏打开云电脑标签，与对话并排使用；收起后可从对话中的入口再次打开。

预览只跟随当前会话实际使用过的云机，不从其他对话借用“最近机器”。同一轮中工具调用之间保留画面；本轮完成后，自动展开的观看画面会收起，机器入口仍保留。手动展开或正在人工接管时不会因一次工具结束而自动打断。

收起人工接管画面时会先交还控制权；切换会话会隐藏旧画面并清理属于预览的接管。消息重绘或内联/侧栏位置切换共用同一个控制器，不由每条消息分别创建接管。放大使用原桌面画面，避免同时打开两个控制连接。

会话活动仅包含机器 ID、状态和操作类型等元数据，观看链接及 API Key 不写入对话消息。活动表保存在本次插件运行的内存中，重载后待该会话再次使用云机才重新出现；已有独立云机、文件与接管清理记录仍按原规则管理。

### 独立云电脑面板

选择机器后启动桌面，可以在插件内观看、全屏或在新窗口打开官方桌面。默认观看链接为服务端强制只读。

点击「接管」后，插件请求官方接管状态，生成可操控链接，同时建立插件内的人工控制租约。键盘、鼠标和剪贴板通过官方 viewer 连接云电脑，API Key 不会交给 iframe。接管期间，本插件的模型工具不能对该机器执行命令、修改文件、变更生命周期或发送键鼠输入；截图等只读操作仍可用。

点击「交还」会撤销该机器的桌面分享链接并交还官方控制状态。官方撤销接口以整台机器为粒度，会断开该机的其他分享 viewer；因此不要在同一机器上依赖其他长期分享链接。仅链接到期不能断开已连接 viewer。

界面切换机器或退出时尝试交还；人工租约有续约与失联回收，浏览器突然关闭也不应永久锁住模型。接管不会自动终止此前已经启动的后台程序；如需停止它们，使用任务列表终止对应后台任务。

接管清理记录保存在设置同目录的 `control-leases.json`，只包含机器 ID、租约标识和时间。DSH 热重载或重启后会先撤销旧连接；失败时显示「上次接管待清理」，模型仍不能变更该机器。可在设置更新失效密钥，再点击「清理并交还」。不要用删除记录文件的方式代替撤销旧桌面连接。

除直接桌面接管外，插件还提供截图、坐标点击/双击、右键/中键、移动、拖拽、滚动、文字输入、快捷键及打开网址。让模型依据截图操作，需要当前模型支持图片输入；纯文本模型可用命令和网页脚本。

`0.1.1` 修复了先观看再接管时仍停留在只读会话的问题：官方观看与接管链接只有 `#token` 不同，插件现在按完整链接重建桌面 iframe。安装新包后重新打开桌面，再接管。

## 资源与用量

进入页面会自动读取当前机器规格、CPU/内存占用、磁盘已用/可用空间、累计运行时长、账户机器和快照配额，以及平台返回的账单信息。各卡片可单独刷新；缺少数据会明确显示未提供，原始响应收在详情中。

「调整机器规格与磁盘」预填服务器当前值，仅提交实际修改的字段。例如只扩容磁盘时不会同时重发 CPU 与内存设置；保存后重新读取当前规格。受套餐或运行状态限制的修改仍由平台校验，插件不会为调整规格自动关机。

## 其他功能

- 云机：列表、详情、模板、创建、启动、暂停、恢复、停止、修改配置、复制、日志、磁盘和删除。
- 命令：前台执行和后台任务，查询日志、结果与终止任务。长任务通过插件任务 ID 查询，不依赖 MCP 的单次 60 秒等待。
- 文件：目录浏览、文本编辑、上传、下载、删除。官方 SDK 单次文件传输最多 10 MiB；插件按同一限制处理，不自动同步整个工作区。
- 快照：列表、详情、创建、删除和从快照创建机器。
- 网络：端口列表、发布和取消发布，支持官方允许的私有访问模式。
- 运维：机器指标、账号/单机用量，以及用用户提供的 SSH 公钥申请短时登录凭证。
- 模型工具：只有一个 `instabox` 入口工具（常驻定义约 1.3KB，0.1.x 为 8 个工具约 8.3KB，外加每个会话 0.8KB 运行时上下文，现已去掉）。各类操作的精确字段和规则由 `help` 按需返回；在设置中关闭模型工具时不注册该工具，不占任何上下文。任务提交和状态查询，桌面截图使用 DSH 附件通道供模型读取。

插件操作的是 Instabox 云机，DSH 现有本地终端和 `/workspace` 的位置不变。机器、快照、资源和运行时长均受 Instabox 账号套餐限制；创建或运行机器可能产生计费。

完整字段见 [操作参考](docs/actions.md)。模型用法：

```json
{"action":"help"}
{"action":"help","input":{"action":"files.write"}}
{"action":"commands.run","machineId":"m_xxx","input":{"cmd":"ls"}}
{"action":"task.get","jobId":"返回的任务ID"}
```

`help` 返回该操作的输入 JSON Schema 和适用规则（接管锁、删除确认等）；未知操作会列出同类可用操作。所有规则仍由插件在执行时强制校验。

## 开发和打包

只在本插件目录执行：

```sh
npm ci --ignore-scripts
npm run check
npm run build
npm test
```

需要离线备用的本地版本包时，再运行 `npm pack --pack-destination ../releases`，每版使用新的版本号和文件名。开发过程不安装到日常 profile。

离线测试覆盖协议、输入校验、凭据边界、接管互斥及浏览器行为。没有真实账号时不能声称完成了官方云端端到端测试。账号安装后的验证步骤见 [实机验证](docs/verification.md)。

发版：在 `master` 上开发和推送不会触发任何构建。改完后递增 `package.json` 版本并提交，打同名标签并推送，例如 `git tag v0.1.4 && git push origin master v0.1.4`。GitHub Actions（`.github/workflows/release.yml`）只在 `v*` 标签推送时运行：检查标签与版本一致，按 lockfile `npm ci`，由 `scripts/release.mjs` 构建、测试，在 `release` 分支上追加一个发布提交（源码加 `lib/`，去掉 `prepare`；父提交是上一个发布提交和该标签的源码提交）并推送。`release` 已有同一或更高版本时会拒绝发版。`npm run release` 可在本地对已打标签的提交生成同样的发布提交（不推送）。
